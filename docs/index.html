Find the program that is quietly wearing out your SSD.

Some software rewrites the same small file thousands of times an hour. Task Manager shows nothing alarming while the drive absorbs gigabytes a day. writehawk finds the loop, tells you whether a known driver bug applies to your machine, and can apply a workaround you can undo.

One command, no administrator rights

Run writehawk scan. For every cause it knows, it says whether you have the hardware, whether your driver has the fix, and whether the writes are happening right now.

> writehawk scan

nvidia-nvtopps-log-rewrite: EXPOSED
  NVIDIA display container rewrites its log file without pause
  Example GeForce card: driver 621.24 (affected from 621.14, fixed in 621.35)
  workaround: available, not documented by the vendor
  why the fix may not have reached this machine:
    - The fix is a hotfix driver. It has to be downloaded and installed by hand.

amd-eeu-dump-files: NOT APPLICABLE
  no amd display adapter in this machine

What it does

01 MEASURE

Sees rewrites, not just bytes

Counts how often each file is written over the same bytes, and how much of that is flushed to the drive. That separates a harmless loop from a harmful one.

02 EXPLAIN

Names the cause

Matches what it sees against a catalog of known bugs, each with its sources, and tells you which driver version fixes it and why that version may not have reached you.

03 ACT

Fixes, with an undo

Shows the exact registry values a workaround would change. Applies them only with --apply, after recording the prior state, and rollback puts everything back.

Run as administrator, the scan also lists heavy rewrite loops that no known cause explains. Those are reported and never acted on.

Why the fix did not just arrive

A vendor publishing a fix and your machine receiving it are separate events. A hotfix driver may be a manual download only. A fix may ship in an optional release while an older one stays recommended. A driver that came from Windows Update or the PC maker is not replaced by the vendor's own releases. writehawk checks which of these applies to your machine and says so.

Built to be safe to run

  • Everything is read-only until you pass --apply from an administrator terminal.
  • A catalog entry can only describe registry values. It cannot run a command.
  • The record of a change is on disk before the change is made, and undo works from that record alone.
  • Undo never overwrites a value that something else has changed since, unless you tell it to.
  • No file content is read and nothing leaves the machine.

Honest limits

  • It is early software. It is tested on Windows 11; Windows 10 has not been run yet.
  • The two rules were checked against a replay of their write pattern, because the real bugs cannot be produced on demand.
  • The vendor's fixed driver is always the better answer. A workaround is for the time until you have it.

Everything that was and was not verified is written down in the research notes.
