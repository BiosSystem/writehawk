Storage Fundamentals

Why Task Manager Hides SSD Wear

Flash memory does not write in individual bytes; it writes in 4KB/16KB pages and erases in massive 256KB–4MB blocks. When software repeatedly rewrites the same file with sync flags, it triggers destructive Write Amplification that standard task managers cannot see.

Healthy Application I/O
Normal Lifecycle

Scenario Selector

What Could Be Wearing Out Your Drive?

Select a scenario below to understand the real-world cause and see writehawk's mitigation.

NVIDIA nvtopps Continuous Log Loop

In driver versions 621.14 through 621.24, NVIDIA's display container service repeatedly rewrote the internal log file nvlog.nvlgstg thousands of times without pause. Users observed gigabytes of SSD writes while their PC sat completely idle.

Official Solution:

Fixed in NVIDIA Hotfix Driver 621.35. writehawk provides a safe 1-command workaround that disables the faulty logging module until you update.

HOW WRITEHAWK HANDLES IT
  • Detects installed driver version and GPU vendor without admin rights
  • Measures live file rewrite activity and disk commitment
  • Records prior configuration into local rollback ledger
  • Can undo anytime with writehawk rollback --apply

Check Your System in 3 Simple Steps

pip install https://github.com/BiosSystem/writehawk/releases/download/v0.2.0/writehawk-0.2.0-py3-none-any.whl

Takes 20 seconds. Changes nothing on your machine and sends zero data over the network:

writehawk scan
3

Read the Clear Summary Result

The final line tells you in plain language what to do:

FIXED / NOT APPLICABLE
You are completely protected. Either the vendor fix is present or the hardware isn't installed. Nothing to do.
EXPOSED / ACTIVE
The loop was detected or the vulnerable version is present. Run writehawk fix <rule> to apply a verified mitigation.
Kernel Internals

Deep Systems Architecture

Standard monitoring tools poll high-level performance counters that lump pipe, socket, and memory writes together. writehawk separates logical cache writes from physical hardware flush events without installing kernel drivers.

Windows Kernel Tracing Engine

Consumes ETW events directly from the OS kernel:

  • Provider: Microsoft-Windows-Kernel-File
  • Isolation: Separates FileIO_Write from FileIO_Flush and lazy-writer paging flushes.
  • Handle Resolution: Queries the system handle table (handles.py) via non-destructive duplicate handles to map files opened prior to trace start.
Rewrite Ratio Formula
Ratio = Total Bytes Written / Distinct Byte Offset Span

Linux & NAS Procfs Engine

Direct procfs & sysfs kernel interface:

  • VFS vs Physical: Compares /proc/<pid>/io VFS characters (wchar) against physical sector writes (write_bytes).
  • Storage Queues: Reads /proc/diskstats and /sys/class/block/*/queue/rotational for TRIM / discard tracking.
  • Btrfs CoW Auditing: Inspects Btrfs subvolumes for active SQLite WAL files running without the NOCOW (chattr +C) attribute.
  • NAS OS Detection: Identifies UGOS Pro, Synology DSM, TrueNAS SCALE, and Unraid automatically.

Measured Benchmark

Real Hardware Probe Measurements

Seven runs of writehawk probe on a quiet NVMe data volume (Windows 11); the traced ratio and flushed bytes come from the three runs made as administrator. Comparing the misleading process counter with the true bytes reaching the physical drive:

Workload Pattern Process Counter File Growth True Volume Bytes Traced Rewrite Ratio Physical Flushed Bytes
rewrite-buffered (5,000 rewrites, no flush) 19.53 MB 0.00 MB 0.02 – 0.03 MB 5,000.0x 0.00 MB (absorbed in RAM)
rewrite-flushed (1,500 rewrites + fsync) 5.86 MB 0.00 MB 13.11 – 13.41 MB 1,500.0x 5.86 MB (forced to NAND)
append-buffered (5,000 block appends) 19.53 MB 19.53 MB 19.71 – 20.15 MB 1.0x 19.53 MB (sequential)

* In rewrite-flushed, every write forces a file system metadata update and flash commit, producing a true write volume exceeding 2.2x the logical write amount.

Diagnostic & Mitigation Catalog

Every rule prints its sources with each result, and every workaround is recorded before it is made so it can be undone. The Windows rules were checked against a replay of each bug's write pattern. The Linux and NAS rules are a preview: they have been run in a Linux container, not yet on a real NAS.
